# 墨源 MoYuan 手册

Anikumo 小说区的引擎说明：它是什么、在 App 里怎么用、兼容范围到哪里、开源信息。

## 这是什么

**墨源（MoYuan）是 Anikumo 作者自研的一个纯 JavaScript 小说聚合引擎**，从 1.0.2 起
作为小说区的唯一引擎运行。它零依赖、不绑定任何平台 API，网络、存储、解码都由宿主
（Anikumo）注入，打包为单个 JS 文件，在 App 内置的 QuickJS 运行时中执行。

它负责的事情只有一件：**按用户导入的书源规则，去解析搜索、发现、详情、目录与正文**，
把不同站点的页面变成统一的书籍数据。引擎本身不内置、不提供任何书源与内容，
源由用户自行导入，内容版权归原站与原作者所有。

主要能力：

- 多源聚合搜索与发现分类（可动态生成的分类同样支持）
- 详情、目录、正文的规则解析（CSS / XPath / JSONPath / 正则 / JS 规则与模板）
- 章节正文的严格分型（文字段落与图片分开处理，支持图片型「漫画书」与音频型有声书源）
- 订阅源（RSS 格式的文章列表与正文阅读）
- 引擎内缓存与并发控制

## 在 Anikumo 里怎么用

普通读者不需要接触引擎本身，只需要书源：

1. **导入**：小说区 →「书源」页 → 从 URL 导入 / 粘贴导入 / 从文件导入 / 从 GitHub 仓库挑选导入。
2. **管理**：点任意书源一行会展开它的信息面板（源链接、分组、源自带说明），
   带登录声明的源有「打开源登录/设置」入口——源的登录表单在 App 内填写提交，不用去源的网站。
3. **排查**：某个源搜不到书、目录为空、正文不对时，用书源管理页里的「源诊断」跑一遍，
   报告会写明卡在哪一步（搜索、详情、目录还是正文），反馈问题时附上诊断结论最有效。
4. **阅读**：章节与正文有会话内缓存，读过的章节来回翻是即时的；读当前章时下一章会
   在后台预取，翻页不用等。

小说区的扩展功能在「小说设置 → 扩展功能」（功能仓库）里按需安装：
语音朗读（系统 TTS、读完自动下一章）与本地书籍（EPUB / TXT 导入）都在那里，
没安装时对应入口在区内完全不存在。

## 兼容范围

墨源支持一类广泛使用的开源书源 JSON 格式，覆盖其主链：
导入、搜索、发现、详情、目录、正文，以及模板、URL 参数、JS 库与登录表单。
以下少数高级能力明确**不支持**（导入这类源时对应功能不生效，诊断会如实标注）：
`preUpdateJs`、`ruleReview`、`webJs`、`java.webView` 等。
我们不宣称与任何既有生态完全兼容；遇到解析不了的源，诊断报告会给出具体失败点。

订阅源（RSS）是另一类导入对象：定义里只有名称与地址、没有书籍规则的条目会被
自动分流到书源管理页的「订阅源」区，与书源分开管理。

## 给开发者

- **接口形状**：引擎对宿主暴露的适配接口与源对象同名同形——
  `search / explore / bookInfo / chapters / content`，宿主（Anikumo、Node、浏览器等）
  只需注入传输层即可运行同一份引擎。
- **零依赖纯 JS**：不依赖 DOM、Node API 或任何 npm 包；可在浏览器、Node、QuickJS、
  Deno、Bun、小程序等运行时中使用。
- **在本仓库中的位置**：打包后的引擎位于 `assets/moyuan/moyuan.js`，
  App 侧宿主与桥接代码位于 `lib/services/novel/`（`moyuan_host.dart` / `moyuan_engine.dart`）。
